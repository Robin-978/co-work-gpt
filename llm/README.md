# 看得見的 LLM — 動態演示語言模型怎麼運作

`llm/index.html` 是一個**單檔、零後端、離線可跑**的網頁，用動畫一步一步演示一個語言模型
從輸入到輸出的完整過程：

1. **Tokenization 分詞** — 文字切成 token，查表換成 id
2. **Embedding 詞向量** — token 向量 ＋ 位置向量
3. **Self-Attention 注意力** — Q·K → softmax → 加權混合 V（含因果遮罩）
4. **Feed-Forward 前饋網路** — 向量維度放大（64 → 192）、GELU、再壓回來
5. **Generation 產生** — logits → 溫度 → softmax → Top-K → 抽樣
6. **Output 輸出** — 新字接回輸入，回到第 1 步（自迴歸）

畫面上的每一個色塊、每一條長條，都是模型**當下在瀏覽器裡算出來的真實數值**，不是預錄的示意動畫。

## 模型

不是呼叫任何 API，而是一個從零訓練的 char-level GPT，權重以 int8 量化後直接內嵌在 HTML 裡：

| 項目 | 值 |
|---|---|
| 參數量 | 128,192 |
| 層數 / 注意力頭 | 2 layers / 4 heads |
| 向量維度 | d = 64（head_dim 16）|
| 前饋層 | 192 |
| 上下文長度 | 48 tokens |
| 字典 | 649 個字元（中文、英文縮寫、數字、標點）|
| 訓練語料 | 325 句，約 34,000 字：III/V 族磊晶半導體 + SPC 統計製程管制用語，另含少量日常句 |

架構跟 GPT 完全一樣（pre-LN Transformer decoder、causal self-attention、weight-tied 輸出頭），
差別只在規模。因為語料極小，它只會講這個領域裡、很像訓練資料的句子——這正好讓「模型在背下來的分布裡取樣」
這件事變得看得見。

語料同時涵蓋磊晶製程與 SPC，還刻意寫了一批交叉句（例如「波長的管制圖出現趨勢，通常和溫度有關」），
所以模型會把兩個領域接在一起講。字典裡也有英文縮寫與數字，剛好可以在 Step 1 看到
`MOCVD` 被切成 5 個 token、而中文一個字只佔 1 個 token 的對比。

內附的 `weights.json` 是訓練到 **第 4,800 步**（loss ≈ 0.09）的檢查點，不是跑完 7,000 步的版本。
這是刻意的：再往下退火會讓機率分布更接近 one-hot，Step 5 的長條圖就只剩一根 100%，
反而看不出 softmax 在做什麼。目前 `MOCVD 的成長` 這個提示會給出
壓 44% / 速 33% / 溫 17%（熵 2.03 bits）——三個都是語料裡真的出現過的接續。

## 重新訓練 / 重新打包

```bash
cd llm/tools
node train.js gradcheck      # 反向傳播的數值梯度檢查
node run_train.js            # 訓練（預設 7000 步、約兩小時），過程中會定期寫出 weights.json
node probe.js                # 驗收：字典健康度、機率分布、實際續寫
node build.js ../index.html  # 把 weights.json 內嵌進 page.template.html
```

超參數可以用環境變數覆寫，不用改程式：

```bash
STEPS=3000 DIM=48 HEADS=3 FF=128 BATCH=12 LR=3e-3 node run_train.js
```

- `corpus.js` — 訓練語料（改這裡就能換模型會講的話）
- `train.js` — 純 JS 的 forward / backward / 梯度檢查
- `run_train.js` — AdamW 訓練迴圈 + int8 量化輸出
- `probe.js` — 檢查工具：語料/字典健康度、機率分布、熵、實際續寫
- `page.template.html` — 網頁模板，`__WEIGHTS__` 會被換成權重
- `build.js` — 打包成單一 HTML

只改網頁不重訓的話，編輯 `page.template.html` 後跑 `node build.js ../index.html` 即可。

## 擴充字典（讓模型認得更多字）

字典不是一份手動維護的清單，而是從語料**自動長出來的**（`run_train.js`）：

```js
const chars = Array.from(new Set(Array.from(text))).sort();  // 語料出現過的字元 = 字典
const cfg = { V: chars.length, ... };
```

所以「擴充字典」＝「**擴充語料 + 重訓**」。沒辦法只加字不重訓：新字的 embedding 是隨機初始化的，
沒被訓練過就只是亂數，模型不會拿它接任何東西。

### 步驟

```bash
cd llm/tools
#（1）編輯 corpus.js 的 SENTENCES，加入新句子
node probe.js                 #（2）看字典健康度：哪些字出現太少
STEPS=4000 node run_train.js  #（3）重訓
node probe.js 1.3             #（4）驗收：分布合不合理、續寫通不通順
node build.js ../index.html   #（5）打包回網頁
```

頁面上的「字典 N tokens」「參數量」是從權重檔讀出來的，不用手動改。
若新增了新主題，記得同時更新 `page.template.html` 裡的預設 prompt 與範例按鈕（`.preset`）。

### 語料要加多少

關鍵不是字典多大，而是**每個字出現幾次**。目前是 34,380 字 ÷ 649 字元 ≈ 每字 53 次。`probe.js` 會直接把出現不到 10 次的字列出來——那些字學不到，
只會變成 Top-K 候選裡的雜訊。

**經驗法則：平均每字 ≥ 20 次，且每個字要出現在多個不同的上下文裡。**
只在一句話裡出現過的字，模型學到的只是「背這句話」。

`buildCorpus()` 把每句重複 6 次，所以一個只出現在一句裡的字＝6 次。加字典時要嘛多寫幾句
用到同一個字，要嘛提高重複次數（但重複不會增加資訊，只會讓它更死記）。

### 規模與代價

| 字典 | d / FFN | 參數量 | 權重（base64） | 訓練成本 | 建議語料 |
|---|---|---|---|---|---|
| 304 | 48 / 128 | 61,120 | ~80 KB | 1.0× | 7 千字 |
| 649（現況） | 64 / 192 | 128,192 | ~172 KB | 2.2× | 3.4 萬字 |
| 1,500 | 64 / 192 | 182,656 | ~238 KB | 3.8× | 4 萬字 |
| 3,000 | 64 / 192 | 278,656 | ~363 KB | 6.5× | 8 萬字以上 |

（訓練成本是相對現在 3,000 步約 16 分鐘而言；輸出層要對整個字典算分數，所以成本大致隨字典線性成長。）

字典超過 ~600 時要把模型調大，否則 48 維裝不下那麼多字的差異（現在的預設已經是 `DIM=64 HEADS=4 FF=192`）。
`DIM` 必須能被 `HEADS` 整除；改 `BLOCK`（上下文長度）也要重訓，因為位置向量表的大小跟著變。
網頁端會自動照權重檔裡的 `cfg` 調整，不用改前端程式。

語料換主題以後，記得同時更新 `page.template.html` 裡的預設 prompt 與 `.preset` 範例按鈕。

### 不建議的做法

把一份常用字表硬塞進語料來「湊字典」。那些字沒有真實的上下文，模型只會學到它們的邊際機率，
在 Top-K 裡冒出來卻接不成句子——字典變大了，輸出品質反而變差。

## 產出有錯的時候怎麼修

模型沒有一張「事實表」可以改。輸出只是三件事的結果：**語料**、**訓練程度**、**取樣設定**。
所以修正一定發生在這三個地方之一——而第一步永遠是**先診斷是哪一種錯**，不要用猜的。

### 第一步：用 probe.js 看出錯那一格的機率分布

```bash
node probe.js 1.3 "Cpk 大於 1.6"
```

關鍵只有一個問題：**正確答案的機率高不高？**

| 診斷 | 意思 | 怎麼修 |
|---|---|---|
| 正確答案機率很高，卻沒被選中 | 抽籤意外 | 降溫度 / 降 Top-K，**不用重訓** |
| 正確答案機率就低 | 模型沒學好 | 補語料變體、提高 `STEPS` |
| 模型很有信心，但講的是錯的 | 語料本身寫錯 | 改 `corpus.js` 重訓 |
| 出現「不在字典」警告 | 沒有這個字 | 擴語料重訓 |

### 實例：`Cpk 大於 1.63`

語料裡只有 1.33（能力足夠）和 1.67（能力很好），但模型曾經吐出 `1.63`。診斷結果：

```
"Cpk 大於 1."   → 6 93.3%  3 3.9%
"Cpk 大於 1.6"  → 7 97.5%  1 0.3%  6 0.2%  3 0.2%   ← 抽到了 0.2% 的「3」
"Cpk 大於 1.33 代表製程的能力" → 足 98.0%   ✓
"Cpk 大於 1.67 代表製程的能力" → 很 99.3%   ✓
```

模型其實知道答案（1.67 有 97.5%），是取樣抽到了 0.2% 的冷門。溫度降到 0.5 時，
同一格的分布變成 `6 100.0%`，這個錯就不會發生了。**這種錯不需要重訓，調溫度就好。**

反過來說，這也是「幻覺」的縮影：每一步都是一次抽籤，一段話跑幾十步，
再小的機率也遲早會被抽中——而且模型不會知道自己抽錯了。

### 對照到真正的 LLM

| 這裡的做法 | 真實世界對應的東西 |
|---|---|
| 降溫度 / 調 Top-K | 完全一樣，就是推論參數 |
| 改語料重訓 | 清理預訓練資料 |
| 針對錯誤補寫正確例句再訓 | 微調（SFT）|
| 人工標出好壞再訓 | RLHF / 偏好對齊 |
| （本模型沒有）查完資料再回答 | RAG 檢索增強 |
| （本模型沒有）輸出後再檢查一次 | 護欄 / 事實查核 |

## 續訓（微調）：不用從頭來過

改一句語料就重訓兩小時太貴。`RESUME=1` 會**接著現有的 `weights.json` 繼續訓練**：

```bash
cd llm/tools
# 改完 corpus.js 之後
RESUME=1 node run_train.js          # 預設 900 步、LR 4e-4，約 18 分鐘
RESUME=1 STEPS=1500 node run_train.js   # 學不夠就再跑久一點
node probe.js 1.3 "你改的那句的開頭"
node build.js ../index.html
```

`RESUME=/path/to/其他檢查點.json` 可以指定別的檔案當起點。

### 它做了什麼

- **字典可以變大**：舊字的詞向量照「字」搬過來，只有新字隨機初始化。所以加句子、加術語都不必從零開始
- **結構不能變**：`DIM` / `LAYERS` / `HEADS` / `FF` / `BLOCK` 必須和檢查點一致，不一致會直接報錯並告訴你該用什麼值
- **預設值不同**：續訓是 900 步 / LR 4e-4（從零訓練是 7,000 步 / LR 2.5e-3）。學習率小才不會把原本學會的東西洗掉
- **會先量一次 loss**：載入後如果印出的是接近原本訓練到的值（例如 0.09），就確認真的接上了；
  如果接近 `ln(字典大小)`（約 6.5），代表根本沒載到
- **會自動備份**：原檢查點複製成 `weights.prev.json`，續訓壞掉可以直接還原

### 實測：續訓能做到什麼、做不到什麼

在 649 字典的模型上加了 12 句「良率與可靠度」（引進 11 個新字元），分兩輪續訓：

**第一輪 900 步（18 分鐘）**——句首學會了，但整句往下會散掉，**全新的字元幾乎沒學起來**：

| 提示 | 正確接續 | 900 步後 |
|---|---|---|
| `良率是通過測試的` | 片（數）| 85.6% ✓ |
| `8D 是一套` | 處（理）| 78.6% ✓ |
| `老化測試可以先` | **篩**（掉）——新字元 | **8.2%**（熵 6.99 bits）✗ |

**第二輪再 1500 步（31 分鐘，累計 2,400 步）**——新字元才真的學起來：

| 提示 | 900 步 | 累計 2,400 步 |
|---|---|---|
| `老化測試可以先` | 篩 8.2% | **篩 64.4%** |
| `8D 是一套` | 處 78.6% | 處 91.5% |
| `可靠度測試是用加速的` | — | 條 98.5% |
| `失效分析要先` | — | 確 89.6% |

**而舊的東西自始至終沒有被洗掉**——這是續訓最該擔心的事（災難性遺忘），實測沒有發生：

| 提示 | 續訓前 | 累計 2,400 步後 |
|---|---|---|
| `量子井的` | 厚 98.5% | 厚 99.1% |
| `Cpk 大於 1.6` | 7 97.5% | 7 97.1% |
| `MOCVD 的成長` | 壓 44 / 速 33 / 溫 17 | 溫 44 / 速 31 / 壓 22 |

（`MOCVD 的成長` 這三個候選是 成長溫度／成長速率／成長壓力，順序換了但三個都對。）

結論很直接：**續訓的成本和它要學會的量成正比**。

- 改錯字、改一句寫錯的話 → 900 步就夠
- 加一小批用**既有字元**寫的句子 → 900～1500 步
- 引進**新字元** → 新字的詞向量等於從零學，要 2,000 步以上；新字很多時乾脆從零重訓

`run_train.js` 在新字超過 40 個時會直接警告你這件事。

### 一個技術細節

檢查點是 int8 量化的，所以續訓等於「反量化 → 訓練 → 再量化」。實測這個來回幾乎沒有損失
（載入後 loss 0.1056，原本訓練到的是 0.09，差距在取樣誤差內），但如果反覆續訓很多輪，
量化誤差會慢慢累積——真的要做很多輪的話，建議每隔幾輪從零重訓一次當基準。

## 操作

- **開始演示 / 暫停 / 停止**（空白鍵 = 開始或暫停，Esc = 停止）
- **溫度**：越低越保守，越高越有創意也越容易亂講
- **Top-K**：只從機率最高的 K 個字裡抽
- **動畫速度**：0.5×–4×
- **每個字都完整演示 / 只完整演示第一個字**：後者會加快後續的字
- 注意力那一段可以切換**第幾層、第幾個頭**，看不同的頭在看什麼關係
